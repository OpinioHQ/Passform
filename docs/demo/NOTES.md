# 시험 데모 기록 (`feat/demo`)

- 목적: 강의 5·6을 끝내기 전에 실제로 만들어 보며 구현 시간과 문제를 파악한다. main 합치기는 아직 정하지 않았다.
- 기준: main `ecc06e2`에서 분기. 추적 파일 변경 0건, 새 파일만 추가.
- 작성: 2026-11-04 (KST)

## 1. 결론

- **"결과 탐색 + 응답 제출"은 노트북에서 실제 LLM까지 끝까지 돈다.** 숫자는 시드 원문과 코드로 대조해 일치했다.
- **가장 큰 위험은 구현량이 아니라 파서다.** 없는 학과를 물으면 조건을 버려 전체 건수가 나갔다. 지금은 코드 보정으로 막았고, 프롬프트 개선은 사람이 승인해야 한다.
- **이 코드를 그대로 정식으로 올릴 수는 없다.** 엣지케이스는 어느 정도 다루지만 강의 5·6 조건은 코드 밖에서 충족되지 않았다(6절).

## 2. 실행 (PowerShell)

처음 한 번: `.env.example`을 `.env`로 복사해 `DB_PASSWORD`를 채운다. `OPENAI_API_KEY`는 OS 환경변수나 `.env`에 둔다.

```powershell
docker compose up -d db
.\gradlew.bat bootRun --args="--spring.profiles.active=demo"   # 백엔드 :8080
cd frontend; npm install; npm run dev                          # 화면 http://127.0.0.1:5173
```

- 시드는 DB가 비어 있을 때만 들어간다. `data/seed`(골든 fixture)는 읽기만 하고 데모 전용 폼은 `data/demo/forms`에 있다.
- 시드로 되돌리기: 백엔드를 끄고 아래를 실행한 뒤 다시 켠다.
  `docker compose exec -T db psql -U passform -d passform -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"`
- 시드 폼: `form_club_recruit`(38건, 버전 2개, 분기, 인젝션·연락처 함정), `form_a`·`form_b`(골든 fixture), `form_event_signup`(다른 사용자 소유, 0건).
- 화면 오른쪽 위에서 데모 계정을 바꾸면 비소유자 차단을 볼 수 있다.

## 5. 실제로 돌려서 나온 문제

### 파서 측정

평가 질문 16개에 프롬프트 규칙대로의 기대값을 둔 비교다. **기대값을 보고 예시를 썼고 튜닝에 쓴 질문이라 수치는 낙관적이다. 별도 평가 세트로 다시 재야 한다.**

| 설정 | 일치 |
|---|---|
| `parse_query.md` v2, effort none (현재) | 5~6/16 (실행마다 다름) |
| 같은 프롬프트, effort low | 5/16 |
| 입력을 태그로 감쌈 / `입력: …` 형식 | 5/16 |
| v2 + 아래 예시 7개, effort none | 13/16 |

같은 입력 반복: "수의학과 학생 수 알려줘" 6회 중 5회가 `conditions: []`다. temperature 0이어도 출력이 달라진다.

## 7. SPEC에 없어 임시로 정한 것 (사람이 확정)

1. 파서 출력 보정 단계(`ParsedContextRepair`).
2. 파서에 발화를 태그 없이 보냄.
3. 분기로 건너뛴 문항의 판정 불가를 `PathAwareEvaluator`로 처리: 잠긴 타입을 안 바꾸려고 건너뛴 문항이 같은 응답끼리 묶어 평가 후 합침. `rb05`·`rb08`·`rb13`은 판정 불가, `rb09`는 미응답으로 갈리는 것을 확인했다. 조건 평가 §3의 q6 한계를 메우지만 **골든이 없어 수용된 것이 아니다.**
4. 버전 사이에 선택지 문구가 바뀐 문항의 정렬은 `unsortable_field`.
5. 표현 → 문항 해석(`QuestionResolver`): 번호는 최신 버전 기준, 문구는 공백 무시 후 일치, 없으면 포함 관계.
6. `demo` 프로필의 스키마 자동 생성(`ddl-auto=update`), snake_case, `open-in-view=false`는 합칠 때 본 설정으로 옮겨야 한다. 이관 도구는 미정.
7. 폼 정의 검증 없음: `form.schema.json`이 아직 없어 시드를 그대로 믿는다.
8. `matched[]`에 `question_note` 추가: 제작자 화면에 문항 번호 대신 문구를 보여 주려고 더했다. SPEC 253행에 없다.
9. 묻기 밑 버튼은 파서를 거치지 않고 확정 요청(`{context}`)을 보낸다. 자연어는 직접 입력할 때만 파서를 탄다.
10. 휴대전화 형식: 010은 11자리, 011·016~019는 10~11자리(팀 결정). SPEC 162행(10~11자리)보다 엄격해서 합칠 때 SPEC을 고쳐야 한다.
