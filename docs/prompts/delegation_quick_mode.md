# E13 빠른 모드와 모바일 제작 위임 기록 (#58)

작성: 프롬프트 세션 초안을 사람이 검토해 발행. 2026-11-10 실행.

## 추천 문항 확정 방식

- 이슈 본문은 "추천 문항은 착수 전 사람이 쓴다"였으나 이번에는 **에이전트 초안을 사람이 검토·수정해 확정**하는 방식으로 바꿨다(사람 결정).
- 승인본은 `docs/question_templates_draft.md`에 남기고, Flyway `V3__insert_question_templates.sql`은 그 표와 한 글자도 다르지 않다(스크립트로 행 단위 대조, 최종 37행).
- 1차 승인 40행 → 2차(이름·휴대폰 번호·생년월일을 기본 정보 `basic_*`로 늘 추천, 겹치는 4행 삭제, 39행) → 3차(대학생이면 목적과 상관없이 학번·학과(전공) `univ_*`, 겹치는 4행 삭제, 37행). 2·3차는 사람이 계획을 승인한 뒤 고쳤다.

## 사람이 정한 것

- 목적 `apply`·`survey`·`reservation`·`quiz`(SPEC 179행 예시), 대상 `high_school`·`university`·`worker`와 "누구나"(`anyone`, 행 없음 — 목적 공통 문항과 기본 정보만). 목적 공통은 audience `all`.
- `GET /question-templates` 순서: 기본 정보 먼저, 그다음 `template_id` 오름차순. 목록 밖·빠진 값은 `400 invalid_request`(새 오류 코드를 만들면 기존 시험 `ApiExceptionHandlerTest`를 고쳐야 해서 기존 코드를 씀).
- 승인된 기존 시험 변경: `SchemaStartupTest` 56행 기대값 `"2"` → `"3"`. 그 밖의 기존 시험은 고치지 않았다.
- "새 폼 만들기"(내가 만든 폼)는 가운데 상자에서 기본·빠른 모드를 고른다. `/creator/forms/new`는 지금처럼 바로 기본 모드 초안을 만든다(기존 시험 `creatorRoutes.test.tsx` 유지). 빠른 모드는 `/creator/forms/new/quick` → `/creator/forms/{form_id}/quick`.
- **모바일에서도 기본 모드를 막지 않는다**(사람 결정). SPEC 47행·AC69(416~417행)의 "모바일 기본 모드 진입 시 데스크톱 안내"와 다르므로 SPEC 정리가 필요하다. 기존 폼 편집은 기본 모드 화면으로 연다.
- 빠른 모드 단계: 1. 목적·대상 → 2. 제목·설명 → 3. 추천 문항 → 4. 폼 미리보기(폼 직접 편집) → 5. 설정·배포. 위 단계 이름을 눌러도 이동하고, 이전·다음은 오른쪽 아래에 나란히 둔다. 미리보기는 테두리 상자로 제작 화면과 구분한다.
- 추천 문항 체크박스는 그 문항이 폼에 들어 있는지를 보인다. 체크를 풀고 "적용하고 다음"을 누르면 빠지고, 새로 체크한 문항은 체크한 순서대로 끝에 들어가며 옆에 "N번"을 보인다. 화면에 요청하지 않은 안내 문구는 넣지 않는다.

## 구현 판단(SPEC·AGENTS 안에서)

- 저장은 기본 모드와 같은 폼 정의와 `POST /forms`·`PATCH /forms/{form_id}`, 자동 저장(`useCreatorAutosave`)을 그대로 쓴다(AC42, AC84). 빠른 모드 전용 저장 형식은 없다.
- 추천 문항 추가는 문구·유형·선택지·`input_format`·`template_id`를 복사하고 `profile_key: null`(AC7). 본인 정보 질문·문항 편집은 기본 모드의 `QuestionEditor`, 설정은 `FormSettingsPanel`, 미리보기는 `ResponsePage preview`를 그대로 쓴다(AC72, AC81).
- 기본 정보 구분은 응답 모양(SPEC 113행 다섯 키)을 늘리지 않으려고 `basic_` 접두사로 한다.
