## 사용자 가이드

처음 Passform을 쓰는 사람이 **응답자**와 **제작자** 두 역할로 핵심 기능을 직접 해 볼 수 있게 정리했습니다. 배포 주소에서 바로 해 보려면 1~7절을, 내 PC에서 띄워 보려면 8절을 보세요.

> [!WARNING]
> **실제 개인정보를 넣지 마세요.** 체험용 폼에는 `김예시`, `010-0000-0000`, `test@example.com`처럼 지어낸 이름과 가짜 연락처를 쓰세요. 실제 이름·학번·전화번호·주소를 넣으면 그 폼의 제작자가 볼 수 있습니다.

### 1. 서비스 소개

| 항목 | 내용 |
|---|---|
| 팀 | 2팀 · Opinio(오피니오) |
| 서비스 | Passform — 응답자 중심의 통합 폼 서비스 |
| 대상 사용자 | 학교·동아리·단체 활동에서 신청·설문 폼에 반복해서 응답하는 대학생(응답자), 그런 폼을 만들어 응답을 모으는 대학생 운영진(제작자) |
| 해결하려는 문제 | 응답자는 여러 폼의 마감과 작성 중인 답, 제출한 답을 따로 챙기기 어렵습니다. 제작자는 모인 응답을 응답 화면과 엑셀 사이를 오가며 손으로 정리합니다. |

계정은 하나이고 누구나 같은 화면을 씁니다. 같은 사람이 폼을 만들기도 하고 응답하기도 합니다.

**이번 MVP의 핵심 기능**

- 응답: 로그인 없이 공유 링크로 응답, 한 질문씩·전체 질문 보기, 작성 중 자동 저장(로그인하면 계정에, 아니면 이 브라우저에), 개인정보 수집·이용 동의 후 제출
- 내 폼함·제출 내역(로그인): 응답 중인 폼과 제출한 폼을 한곳에서 보고(탭: 전체·작성 중·미제출·마감됨, 정렬 변경), 제출한 답을 다시 보기. 제작자가 허용한 폼은 제출 후 수정·취소
- 마감 알림(로그인): 내 폼함에 저장하고 아직 제출하지 않은 폼은 마감 24시간 전에 사이트 알림과 메일로 한 번 알림. 오른쪽 위 사용자명을 눌러 끄기
- 내 프로필과 자동채우기(로그인): 프로필을 여러 개 저장해 두고, 제작자가 본인 정보라고 표시한 문항에서 "내 정보로 채우기"
- 폼 만들기(로그인): 섹션·문항 추가, 문항 유형 5종(단답형·장문형·단일 선택·복수 선택·드롭다운), 입력 형식, 최대 글자 수, 조건분기, 미리보기, 분기 흐름 보기, 마감·선착순 인원·수정/취소 허용·AI 요약 설정, 배포 전 초안 자동 저장, 배포와 공유 링크·QR, 폼 복제
- 결과 대시보드(그 폼의 제작자만): 전체 응답 수, 문항·선택지 통계(통합 보기·버전별 보기), 단답·장문 답 목록, 내보내기(JSON·YAML·CSV)
- AI 결과 탐색(그 폼의 제작자만): 결과 화면 오른쪽 "탐색 도우미"에 평소 쓰는 말로 물으면 조건에 맞는 응답 수, 요약과 근거 발췌를 보여 줍니다. 확정할 수 없는 질문은 추측하지 않고 되묻습니다.

### 2. 접속과 계정

| 항목 | 내용 |
|---|---|
| 접속 주소 | https://app.passform.kr |
| 백엔드 상태 확인 | https://api.passform.kr/health → `{"status":"ok"}` |
| 저장소 | https://github.com/OpinioHQ/Passform (브랜치 `main`) |
| 예시 폼 | https://app.passform.kr/f/Ui3ECL00PybHgYe4zrbzBA |
| 지원 환경 | 데스크톱 Chrome·Edge 최신 버전. 응답은 휴대폰 Safari에서도 됩니다. 설치할 것은 없습니다. |
| 계정 | 본인 Google 계정으로 로그인합니다. 테스트 계정은 따로 주지 않습니다. |
| 개인정보처리방침 | https://app.passform.kr/privacy.html (홈 화면 맨 아래 링크) |

- **응답만 할 때는 로그인이 필요 없습니다.** 공유 링크를 열고 바로 답하면 됩니다.
- 내 폼함, 제출 내역, 내 프로필, 폼 만들기, 결과 보기에는 로그인이 필요합니다. 화면 오른쪽 위 "로그인" → "Google로 로그인"을 누르세요.
- 로그인하면 Passform 첫 화면으로 돌아옵니다. 응답하던 폼이 있었다면 그 링크를 다시 여세요.
### 3. 전체 흐름

| 역할 | 체험 목표 | 필요한 것 |
|---|---|---|
| 응답자 | 예시 폼에 응답하고, 내 폼함과 제출 내역에서 다시 확인한다 | 브라우저(로그인은 선택) |
| 제작자 | 내 폼을 만들어 배포하고, 모인 응답을 결과 화면과 AI 결과 탐색으로 확인한다 | Google 계정, 시크릿 창이나 친구(응답 넣기용) |

### 4. 체험 1 응답자

**가정:** 동아리에 지원하려는 학생입니다. 운영진이 보낸 지원서 링크로 지원서를 냅니다.

**예시 답 A** (그대로 써도 됩니다)

| 문항 | 예시 답 A |
|---|---|
| 이름 | 김예시 |
| 학과 | 소프트웨어학과 |
| 학년 | 2학년 |
| 연락 이메일 | test-a@example.com |
| 지원 분야 | 개발 |
| 면접 가능 시간 | 평일 저녁, 주말 오후 |
| 지원 동기 | 팀 프로젝트로 실제 서비스를 만들어 보고 싶어서 지원했습니다. |
| 동아리에 바라는 점 | 스터디 일정을 미리 알려 주시면 좋겠습니다. |

**A. 로그인 없이 응답하기**

| 누르는 것 | 보이는 것 |
|---|---|
| 2절의 예시 폼 링크를 연다 | 폼 제목과 첫 질문. 위에 현재 단계와 남은 분량이 보입니다. |
| 답을 쓰고 "다음" | 다음 질문. 필수 문항을 비우거나 형식이 틀리면 그 문항 아래에 이유가 보입니다. |
| (선택) "전체 질문 보기" | 한 페이지에 모든 질문. 분기가 없는 폼에서만 바꿀 수 있습니다. |
| 답을 쓰는 중 | "이 브라우저에 저장됨". 창을 닫았다가 같은 브라우저로 다시 열면 이어 쓸 수 있습니다. |
| 마지막에 "개인정보 수집·이용에 동의합니다 (필수)"를 체크 | 동의하지 않으면 제출되지 않습니다. 각 문구 옆 "내용 보기"로 수집 항목·목적·보유 기간을 볼 수 있습니다. |
| (선택) "AI 요약을 위한 외부 전송에 동의합니다 (선택)"를 체크 | 체크하지 않아도 제출됩니다. 체크한 응답만 제작자의 AI 요약에 쓰입니다. |
| "답변 제출" | "제출 완료" 표시와 "응답을 제출했어요" 화면 |

**B. 로그인하고 응답하기** — 내 폼함과 제출 내역까지 봅니다.

| 누르는 것 | 보이는 것 |
|---|---|
| 오른쪽 위 "로그인" → "Google로 로그인" | Google 계정 선택 뒤 Passform 첫 화면. 오른쪽 위에 내 이름이 보입니다. |
| 예시 폼 링크를 다시 연다 | 응답 화면에 "내 폼함에 저장" 버튼. 로그인 전에 이 브라우저에서 쓰던 답이 있으면 이어 쓸지 묻습니다. |
| "내 폼함에 저장" | "내 폼함에 저장했어요". 답을 쓰기 시작해도 내 폼함에 들어갑니다. |
| 답을 쓰고 동의 후 "답변 제출" | "응답을 제출했어요" |
| 위 메뉴 "내 폼함" | 예시 폼이 "제출함" 표시와 함께 "전체" 탭에 보입니다. 정렬을 바꾸거나 폼 이름으로 검색할 수 있습니다. |
| 위 메뉴 "제출 내역" | "제출 내역" 화면. 목록에서 폼을 고르면 제출 당시 문항과 내 답이 보입니다. |
| (제작자가 허용한 폼만) "답변 수정" | 제출한 답을 고쳐 "수정 저장" → "답변을 수정했어요" |

**C. QR로 휴대폰에서 응답하기** — 휴대폰 카메라로 폼의 QR을 찍거나 예시 폼 링크를 휴대폰에서 열면 같은 응답 화면이 열립니다. QR은 폼을 만든 사람이 빌더나 "내가 만든 폼"의 "QR 보기"로 띄워 줍니다(5절). 답을 쓰는 방법은 A·B와 같습니다.

> 마감 알림: 마감이 24시간 안으로 남은 폼을 내 폼함에 저장하고 제출하지 않으면, 몇 분 안에 오른쪽 위 종 아이콘에 안 읽은 알림 수가 보이고 로그인한 Google 메일로 "[Passform] 마감 24시간 전: (폼 제목)" 메일이 한 번 옵니다. 알림을 누르면 그 폼이 열립니다. 오른쪽 위 사용자명을 누르면 펼쳐지는 메뉴에서 "마감 하루 전 알림"을 끄거나 로그아웃할 수 있습니다.

> 내 프로필(위 메뉴 "내 프로필")에 예시 정보를 저장해 두면, 제작자가 본인 정보라고 표시한 문항에서 "내 정보로 채우기"로 값을 채울 수 있습니다. 채운 값은 제출 전에 확인하고 고칠 수 있습니다.

### 5. 체험 2 제작자

**가정:** 동아리 운영진입니다. 지원서를 만들어 돌리고, 모인 지원서를 확인합니다.

> 결과 대시보드와 AI 결과 탐색은 **그 폼을 만든 사람만** 볼 수 있습니다. 다른 사람의 폼 결과 주소를 열면 "이 폼을 만든 사람만 볼 수 있어요."가 보입니다.

**A. 폼 만들기와 배포**

| 누르는 것 | 보이는 것 |
|---|---|
| Google로 로그인 → 위 메뉴 "내가 만든 폼" | 내가 만든 폼 목록(처음에는 "아직 만든 폼이 없어요.") |
| "새 폼 만들기" → "기본 모드" | 폼 편집 화면. 제목·설명 칸과 빈 섹션 하나. 배포 전 초안은 입력을 멈추면 자동으로 저장되고 "저장됨"이 보입니다. |
| 폼 제목에 `○○ 동아리 지원서`를 쓰고 "문항 추가" | 문항 카드. 문구, 문항 유형, 입력 형식, 필수 여부를 정합니다. 4절 표처럼 문항 몇 개를 만들어 보세요. 지원 동기처럼 길게 쓰는 문항은 "장문형"으로 둡니다. |
| "폼 설정"에서 "AI 요약 사용" 체크 | AI 요약을 쓰려면 **첫 배포 전에** 켜야 합니다. 배포 뒤에는 바꿀 수 없습니다. 필요하면 "제출 후 수정 허용"·"제출 취소 허용"도 체크합니다. 개인정보 동의서는 기본 템플릿이 골라져 있습니다. |
| "미리보기" | 응답자가 보는 화면. 미리보기에서는 제출되지 않습니다. |
| "배포" | "배포했어요 · 폼 버전 1". "폼 설정"에 공유 링크와 "링크 복사"가 생깁니다. |
| "QR 보기" | 공유 링크를 담은 QR. "PNG 내려받기"로 이미지를 받을 수 있습니다. "내가 만든 폼" 목록의 공유 링크 옆에도 있습니다. |
| (빠른 모드로) "새 폼 만들기" → "빠른 모드" | 목적(신청·설문조사·예약·퀴즈)과 대상(고등학생·대학생·직장인·누구나) → 제목·설명 → 추천 문항(이름·휴대폰 번호·생년월일은 늘 추천) 체크 → 폼 미리보기("폼 직접 편집"으로 고치기·직접 질문 추가) → 설정·배포. 휴대폰에서도 됩니다. 만든 폼은 기본 모드에서도 똑같이 열립니다. |
| 배포 뒤 문항을 고쳤다면 "변경 저장" | 배포한 폼은 자동 저장되지 않습니다. "변경 저장"을 눌러야 응답자 화면에 반영됩니다. |

**B. 응답 넣기** — 공유 링크를 시크릿 창에서 열거나, QR을 휴대폰으로 찍거나, 친구에게 보내 3건 이상 응답합니다. 4절의 예시 답 A와 6절의 예시 답 B·C를 섞어 쓰고, AI 요약을 보려면 선택 동의도 체크하세요.

**C. 결과와 AI 결과 탐색**

| 누르는 것 | 보이는 것 |
|---|---|
| "내가 만든 폼" → 내 폼의 "결과 보기" | "결과 대시보드". 위에 "전체 응답 N건", 문항별 선택지 통계와 단답·장문 답 목록. "통합 보기"와 버전 탭을 오갈 수 있습니다. |
| 오른쪽 "탐색 도우미" 입력칸에 질문을 쓰고 보내기(→) | 도우미 말풍선 뒤, 대시보드 위에 "AI 탐색 결과"가 뜹니다. |
| 입력칸 아래 버튼 | 이 폼에서 물을 수 있는 질문 모음입니다. 누르면 글로 쓰지 않고 바로 묻습니다. |

**예시 질문** (예시 폼 문항 기준, 내 폼이면 문항 이름에 맞게 바꾸세요)

| 질문 | 기대 결과 |
|---|---|
| 소프트웨어학과 지원자 몇 명? | "조건에 맞는 응답 N건을 찾았어요." 결과의 "연결 결과"에 어느 문항·선택지로 찾았는지 보입니다. |
| 전체 응답 요약해줘 | 주제별 요약과 주제마다 응답 개수, 근거가 된 답 발췌 |
| 지원 동기 요약해줘 | 지원 동기 문항만 모은 주제별 요약과 근거 |
| 프로젝트 경험을 쌓고 싶다는 의견 요약해줘 | 그 의견에 해당하는 답만 모은 요약과 근거(이 유형은 개수를 보이지 않습니다) |
| 소프트웨어학과 지원 동기 요약해줘 | 소프트웨어학과 응답의 지원 동기만 요약 |

결과 화면에서는 응답을 "응답 1", "응답 2", 폼 버전을 "폼 버전 1"처럼 부르고, 문항은 문구로 보여 줍니다. 일부 응답만 확인할 수 있었으면 그 사실이 항상 보이고, 이유는 옆의 "?"를 누르면 보입니다. "이 결과 내보내기"를 누르면 그 결과만 파일로 받을 수 있습니다.

### 6. 기대 결과와 확인 방법

**정상이면 이렇게 됩니다**

- 응답자: "응답을 제출했어요" 화면이 뜨고, 로그인했다면 "내 폼함"에 그 폼이 "제출함"으로, "제출 내역"에 제출한 답이 보입니다.
- 제작자: "결과 대시보드"의 "전체 응답 N건"이 넣은 응답 수와 같고, 선택지 통계가 넣은 답과 맞습니다.
- AI 결과 탐색: "소프트웨어학과 지원자 몇 명?"의 건수가 대시보드의 학과 통계에서 소프트웨어학과 수와 같습니다. 요약의 근거 발췌가 실제로 넣은 답에서 나왔고, AI 요약에 동의하지 않은 응답은 요약에서 빠졌다고 안내됩니다.

**최종 확인:** 제작자로 결과 대시보드의 "내보내기" → CSV → "파일 받기"로 받아 열면 넣은 응답이 한 줄씩 들어 있습니다.

**다른 입력으로 다시 해 보기**

| 문항 | 예시 답 B | 예시 답 C |
|---|---|---|
| 이름 | 이예시 | 박예시 |
| 학과 | 경영학과 | 소프트웨어학과 |
| 학년 | 3학년 | 1학년 |
| 연락 이메일 | test-b@example.com | test-c@example.com |
| 지원 분야 | 홍보 | 기획 |
| 면접 가능 시간 | 평일 오후 | 주말 오후 |
| 지원 동기 | 동아리 행사를 알리는 홍보물을 직접 만들어 보고 싶습니다. | 프로젝트 경험을 쌓고 기획 역량을 키우고 싶습니다. |
| 동아리에 바라는 점 | (비워 둠) | 면접 시간을 미리 알려 주세요. |

- B·C로 더 응답한 뒤 같은 질문을 다시 해서 건수와 요약이 바뀌는지 봅니다.
- 다른 질문: "경영학과 지원자 몇 명?", "동아리에 바라는 점 요약해줘", "경영학과 지원 동기 요약해줘", "면접 시간을 알려 달라는 의견 요약해줘"
- AI 요약 선택 동의를 하지 않은 응답을 하나 넣고 요약을 다시 물으면, 그 응답이 요약에서 빠졌다는 안내가 보입니다.
- 다른 폼으로: "내가 만든 폼"에서 만든 폼의 "복제"를 누르면 복사본의 편집 화면이 열립니다. 문항이나 설정을 바꿔 다시 배포해 봅니다.

### 7. 제한과 알려진 오류

**아직 없는 기능**

- 파일 첨부(폼 설명·문항·응답)는 배포 서버에 파일 저장소가 아직 설정되지 않아 쓸 수 없습니다. 폼 삭제, 받은 응답 전체 삭제, 저장 공간 확인은 됩니다.
- 송금 링크는 새 폼에 넣을 수 없습니다(다시 설계 중).

**알아 둘 점**

- 로그인 없이 쓰던 답은 **그 브라우저에만** 남습니다. 다른 브라우저·기기에서는 이어 쓸 수 없고, 브라우저 저장 데이터를 지우면 사라집니다.
- AI 요약은 "AI 요약 사용"을 켜고 배포한 폼에서, AI 요약에 동의한 응답만 씁니다. 동의한 응답이 없으면 요약하지 않았다고 안내합니다.
- "가장 많이 나온 의견은?" 같은 빈도 질문은 요약 대신 되물을 수 있습니다. 이때는 "○○ 요약해줘"처럼 문항이나 의견을 정해 다시 물어 주세요.
- 이름·연락처·이메일처럼 개인정보 문항의 답은 AI에 보내지 않고, 다른 답 속 전화번호·이메일은 가린 뒤 보냅니다. 그래서 요약에는 이런 값이 나오지 않습니다.
- 마감이 지났거나 선착순 인원이 찬 폼은 열리지 않고 마감 안내가 보입니다.

**문제가 생기면**

| 증상 | 해결 |
|---|---|
| 내 폼함·제출 내역에서 로그인하라고 나온다 | 오른쪽 위 "로그인"으로 Google 로그인 후 다시 엽니다. |
| "로그인하지 못했습니다" | 다시 시도합니다. 계속되면 다른 Google 계정이나 시크릿 창으로 해 봅니다. |
| "열어 둔 폼이 최신이 아니라 제출하지 않았어요" | 응답 중에 제작자가 폼을 바꿨습니다. "최신 폼 다시 열기"를 눌러 처음부터 응답합니다. |
| 탐색 도우미가 "AI 분석을 지금 쓸 수 없어요" | 잠시 뒤 다시 묻습니다. 로컬 실행이면 OpenAI 키가 없는 경우입니다(8절). |
| 결과 화면이 "이 폼을 만든 사람만 볼 수 있어요." | 폼을 만든 계정으로 로그인했는지 확인합니다. |

### 8. 로컬에서 직접 실행하기

배포 주소 대신 내 PC에서 띄우는 방법입니다. 로컬 DB는 비어 있어서 예시 폼이 없으니, 로그인한 뒤 5절대로 직접 폼을 만들어 체험합니다(`data/seed/`는 테스트용 데이터라 DB에 넣지 않습니다).

**필요한 도구:** Git, JDK 17 이상, Node.js 20 이상, Docker(Docker Desktop)

**1) 저장소 받기**

```bash
git clone https://github.com/OpinioHQ/Passform.git
cd Passform
```

**2) 환경 파일 만들기** — 저장소 루트에서 `.env.example`을 `.env`로 복사하고 `DB_PASSWORD=`에 로컬용 아무 비밀번호를 넣습니다. `.env`는 커밋하지 않습니다.

```bash
cp .env.example .env              # Windows PowerShell: Copy-Item .env.example .env
```

**3) Google 로그인 준비** — 로그인과 폼 만들기에 필요합니다. 없어도 앱은 뜨지만 로그인만 실패합니다.

1. [Google Cloud Console](https://console.cloud.google.com/)에서 OAuth 동의 화면을 만들고(테스트 모드면 내 계정을 테스트 사용자로 추가), "OAuth 클라이언트 ID"를 "웹 애플리케이션"으로 만듭니다.
2. 승인된 리디렉션 URI에 `http://localhost:8080/login/oauth2/code/google`을 넣습니다.
3. 받은 값을 백엔드를 띄울 터미널의 OS 환경변수로 넣습니다(또는 `.env`의 `GOOGLE_CLIENT_ID`·`GOOGLE_CLIENT_SECRET` 줄 앞 `#`을 지우고 값을 넣습니다. 값을 비운 채 `#`만 지우면 앱이 뜨지 않습니다).

**4) OpenAI 키(선택)** — AI 결과 탐색에만 쓰입니다. 본인 OpenAI 키를 OS 환경변수 `OPENAI_API_KEY`로만 넣고 `.env`나 저장소에는 넣지 않습니다. 키가 없어도 앱·빌드·테스트는 동작하고, 탐색 도우미에 묻을 때만 "AI 분석을 지금 쓸 수 없어요" 안내가 나옵니다.

```bash
# macOS/Linux (bash)
export GOOGLE_CLIENT_ID=...  GOOGLE_CLIENT_SECRET=...  OPENAI_API_KEY=...
```

```powershell
# Windows PowerShell (이 창에서만 유지됩니다)
$env:GOOGLE_CLIENT_ID = "..."; $env:GOOGLE_CLIENT_SECRET = "..."; $env:OPENAI_API_KEY = "..."
```

**5) DB 띄우기** — 저장소 루트에서

```bash
docker compose up -d db
```

**6) 백엔드 띄우기** — 3)·4)의 환경변수를 넣은 같은 터미널에서. 첫 실행 때 DB 테이블이 자동으로 만들어집니다.

```bash
./gradlew bootRun                 # Windows PowerShell: .\gradlew.bat bootRun
```

http://localhost:8080/health 가 `{"status":"ok"}`면 정상입니다.

**7) 프론트 띄우기** — 새 터미널에서

```bash
cd frontend
npm ci
cp .env.example .env              # Windows PowerShell: Copy-Item .env.example .env
```

`frontend/.env`에서 `VITE_USE_API=true`로 바꿉니다(`false`면 서버 없이 가상 데이터 미리보기만 보입니다). `VITE_API_BASE_URL=http://localhost:8080`은 그대로 둡니다.

```bash
npm run dev
```

**8) 접속** — http://localhost:5173 을 열고 "로그인" → "Google로 로그인" → 오른쪽 위에 내 이름이 보이면 5절부터 진행합니다.

| 주소 | 용도 |
|---|---|
| http://localhost:5173 | 화면 |
| http://localhost:8080/health | 백엔드 상태 |
| localhost:5432 | PostgreSQL(`.env`의 DB 값) |

이 가이드는 11/11~11/18 동안 서비스와 예시 폼을 유지하며, 주소나 실행 방법이 바뀌면 함께 고칩니다.

**주요 브랜치 종류 (Branch Strategy)**

- **`main` (또는 `master`):** **최종 완제품 브랜치.** 버그 없이 완전히 작동하는 대표 코드만 존재하며, 여기서 직접 작업하거나 `git push`하는 것은 금지합니다(사소한 변경 규칙의 예외 제외).
- **`{tag}/...` (작업 브랜치):** **각자의 작업실**입니다. 기본은 최신 `main`에서 새 브랜치를 만들고, 아직 머지되지 않은 다른 작업이 필요하면 그 브랜치에서 만들 수 있습니다. 머지된 브랜치에서 추가 수정을 이어 갈 때는 먼저 최신 `main`을 받아온 뒤 작업합니다.

- 문서의 오타·띄어쓰기·깨진 링크 수정은 이슈·PR 없이 `main`에 바로 push해도 됩니다. 커밋은 `docs: 오타 수정`처럼 남깁니다.

- 단, 판정에 쓰이는 값(골든 케이스 기대값, 스키마의 enum·필수 항목, 임계값)과 프롬프트 본문은 오타라도 PR로 올립니다.
