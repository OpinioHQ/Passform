# 응답 화면 위임 기록 (#52)

## §1 결함 주입

하나씩 임시로 넣고 기대한 테스트 파일만 `vitest run --reporter=json`으로 돌린 뒤 되돌렸다. JSON 결과에서 기대한 테스트가 실제로 실행됐고(`passed` 또는 `failed`) 실패했는지를 확인했다. 되돌린 뒤 바꾼 파일의 해시가 주입 전과 같은 것을 확인했다. 주입은 커밋하지 않았다.

| 주입 | 바꾼 곳 | 기대 실패 | 실제 결과 |
|---|---|---|---|
| 오류를 "다음"을 누르기 전에 표시 | `ResponsePage.tsx` `update` | 입력 중에는 오류를 보이지 않고 "다음"을 누르면 그 문항 아래에 보인다 | 실행됨, 실패. 36건 중 이 1건만 실패 |
| 동의 없이 제출 버튼 활성화 | `ResponsePage.tsx` 제출 버튼 `disabled` | submit_without_consent의 화면 | 실행됨, 실패. 1건만 실패 |
| 송금 링크를 https 확인 없이 연다 | `ResponsePage.tsx` `isHttpsLink` | `%s는 링크로 열지 않는다` | 실행됨, 실패. `http://`, `javascript:`, `//`, 글자 4건 모두 실패 |
| 보기 전환 시 답을 버린다 | `ResponsePage.tsx` `switchView` | unbranched_respondent_switch_preserves_answers | 실행됨, 실패. 1건만 실패 |
| 글자 수 초과를 막지 않는다 | `answerCheck.ts` `checkAnswer` | 101자는 입력은 남기되 제출을 막고, 정확히 100자는 제출된다 | 실행됨, 실패. 1건만 실패 |
| 여러 규칙이 맞을 때 마지막 규칙 | `responsePath.ts` 규칙 검사 순서 뒤집기 | AC44_여러_규칙이_맞으면_위의_규칙을_따른다 | 실행됨, 실패. 14건 중 1건만 실패 |
| 건너뛴 문항의 답이 뒤 분기에 영향 | `responsePath.ts` 분기 조건에 전체 답 사용 | 건너뛴_문항에_보낸_답은_뒤의_분기에_영향을_주지_않는다 | 실행됨, 실패. 1건만 실패 |

- 주입은 1회차 코드에서 했다. 2회차는 CSS 한 줄과 형식 테스트 2줄을 더했을 뿐이고 주입 대상 코드는 바뀌지 않았다.
- 4회차(main #81 합친 뒤)에 같은 7건을 다시 돌렸다. 화면 테스트 파일 이름이 `ResponsePage.screen.test.tsx`로 바뀌었고, 7건 모두 실행돼 기대한 테스트만 실패했다.

## §2 경로 계산 일치 (AGENTS.md 5절 "같은 응답 경로 계산")

사람 결정 A안대로 화면은 `frontend/src/response/responsePath.ts` 한 파일에서 경로를 계산한다. 서버에 경로를 보내지 않고 경로 API도 더하지 않았다. 두 계산이 같은 결과를 내는지는 아래 두 가지로 확인한다.

**골든 케이스 직접 읽기** (`responsePath.golden.test.ts`): `tests/harness/golden_cases.yaml`(`yaml` 패키지)과 `data/seed/forms/*.json`(`import.meta.glob`)을 원본 그대로 읽는다. 케이스를 코드에 복사하지 않는다.

| 골든 | 화면 계산 | 기대값과 비교 |
|---|---|---|
| `skipped_answers_dropped` | 경로 위 문항의 답만 남김 | `expect_saved_answers`와 같다. 건너뛴 답이 실제로 있었는지도 확인 |
| `required_missing_visited_only` | 지나온 필수 빈 문항 | `expect_question_ids` `[q4]`와 같다. 건너뛴 필수 문항이 있었는지도 확인 |

- https가 아닌 송금 링크는 링크로 만들지 않고 "안전하지 않은 주소라 링크를 열지 않아요."라고 보인다(서버도 저장할 때 막는다).
