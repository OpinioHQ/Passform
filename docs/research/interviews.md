### A.인터뷰 프로토콜

**대상(누구를, 왜 — 행동 조건을 넣어서):** 

#### 설문조사 제작자

**유형 A. 높은 응답률 지향형 — 교원·교육기관/단체 운영·관리 담당자**

- **대상:** 다수의 구성원을 대상으로 설문·신청 폼을 직접 제작하고, 실제로 많은 응답을 수집·관리해 본 경험이 있는 사람
- **이유:** 반복적으로 폼을 제작·배포하면서 **응답률을 높이기 위해 어떤 방식을 사용했는지**, 그리고 다양한 폼 서비스를 사용하며 겪은 불편과 요구사항을 파악할 수 있다.

**유형 B. 정교한 데이터 수집형 — 연구자·창업가·마케터·기획자**

- **대상:** 조사·연구·마케팅·서비스 기획 등을 위해 복잡한 질문 구조의 폼을 직접 설계하고, 응답 데이터를 분석·활용해 본 경험이 있는 사람
- **이유:** 조건부 질문, 다양한 응답 형식 등 **정교한 설문을 설계하는 과정에서 발생하는 어려움**과 수집된 데이터를 활용하기 위한 요구사항을 파악할 수 있다.

#### 설문조사 응답자

**유형 C. 의무형 응답자 — 중·고등학생, 대학생·대학원생, 취업준비생**

- **대상:** 학교·대학·기관 등에 소속되어 있거나 지원 과정에 있어, 수업·행정·지원·신청 등의 목적으로 설문이나 폼에 **반복적으로 응답해 본 경험이 있는 사람**
- **이유:** 자발적 관심보다는 **소속이나 필요에 의해 폼에 응답하는 상황**에서 어떤 요인이 응답을 귀찮게 하거나 중도 이탈을 유발하는지 파악할 수 있다.

**유형 D. 보상 추구형 응답자 — 20~30대 일반 설문 참여자**

- **대상:** 리워드, 경품, 이벤트 참여 등의 보상을 목적으로 온라인 설문이나 폼에 응답해 본 경험이 있는 20~30대
- **이유:** **보상이 응답 동기와 완료율에 미치는 영향**, 그리고 보상 수준·설문 길이·응답 난이도에 따라 참여 여부를 결정하는 기준을 파악할 수 있다.

- **알아내려는 것(가설 — 틀릴 수 있는 문장으로):** 설문 참여를 주저하게 만드는 진짜 원인은 “응답 과정의 피로도와 개인정보 입력 부담”이며 , 응답자 친화적인 폼은 편리함을 통해 설문조사 응답률을 높여 윈윈(Win-Win) 구조를 만든다.
- **질문 5개 (각 질문 옆에 의도 한 줄):**
    - 제작자
        1.  폼을 어떤 환경에서 사용하기 위해 제작하셨나요? — 폼이 주로 사용되는 환경과 목적을 알아보기 위해서
        2. 설문조사를 제작할 때 **주로 어떤 서비스**를 사용하십니까? — 사람들의 폼 서비스 선호도를 조사
        3. 해당 서비스를 주로 사용하신 가장 큰 이유는 무엇이었나요? — 사람들의 폼 서비스 선택 이유를 알아보기 위해서
        4. 설문조사 응답 수집 과정에서 불편했던 점은 무엇인가요? — 경험에서 나오는 기존 서비스의 문제점을 조사
        5. 응답 수집 과정의 문제를 해결하기 위해 시도한 행동은 무엇인가요? — 기존 서비스의 문제를 해결하는 사용자의 우회로를 알아보고 더 나은 개선점을 고안하기 위해
    - 응답자
        1. 1년 간 설문조사에 응답하는 대략적인 횟수는? — 사용자의 참여도를 알아보고 이에 따른 개별 질문을 위해
        2. 설문조사 응답을 망설이게 만드는 가장 큰 이유는 무엇입니까? — 응답 참여율을 낮추는 이유를 알아보기 위해
        3. 설문에 참여할 마음이 들게하는 이유는 무엇입니까? — 응답 비선호자를 설문조사에 유도하는 방법을 알아내기 위해
        4. 응답하기 편하다고 느끼는 설문조사 형태는 무엇입니까? — 응답 참여율을 높이는 요소(디자인, 구성, 환경 등)을 알아보기 위해
- 우리가 특히 조심할 유도 질문: 
❌ 자동 응답 기능이 있는 폼 서비스가 있다면, 사용하실건가요? 
→ ✅ 주로 사용하는 폼 서비스가 무엇인가요? 해당 서비스를 사용하는 이유(장단점)은 무엇인가요?

**도출된 페인 (누적 — 각 항목에 범주와 로그 번호 필수)**

1. **응답자 페인**
    1. **반복 입력 및 직접 작성 부담** [문제] — 이름·전화번호와 같은 기본 정보를 반복해서 입력하거나 주관식 문항을 직접 작성해야 해 응답 과정의 시간과 피로가 증가함. (로그 3, 7, 10)
    2. **제출 내용 재확인의 어려움** [제약] — 제출 이후 자신이 작성하거나 선택한 내용을 다시 확인·수정하기 어려워 오입력이나 미입력 여부에 대한 불안이 발생함. (로그 3, 4, 6)
    3. **개인정보 제공에 대한 신뢰 부족** [문제] — 개인정보가 어떻게 사용되고 처리되는지에 대한 신뢰가 부족해 개인정보 요구 자체에 불안이나 반발심이 발생하고 이로인해 설문 기피 현상이 발생함 (로그 4, 9)
    4. **장문 설문으로 인한 응답 중단** [실패 유형] — 설문의 분량이 길어질수록 응답자가 설문을 중간에 중단하는 경험이 발생함. (로그 1, 4, 8, 9)
    5. **파일 업로드 과정의 제약** [제약, 실패 유형] — 파일이 정상적으로 업로드되지 않거나 용량 제한이 있으며, 구글 드라이브 등을 통한 업로드 과정도 번거로워 제출에 어려움이 발생함. (로그 1, 2)
    6. **외부 서비스 이용에 따른 응답 흐름 단절** [우회로, 실패 유형] — 외부 링크 접속 시 로그인이나 접근 제한이 발생하고, 계좌이체·과거 이력 확인 등을 위해 외부 앱으로 이동하면서 설문 흐름이 끊김. (로그 2, 10)
    7. **마감기한 경과에 따른 제출 실패** [실패 유형] — 응답 의사가 있어도 마감기한을 놓치면 폼 제출 자체를 완료하지 못함. (로그 2, 8)
    8. **문항 구성에 따른 응답 피로** [문제] — 지나치게 세분화된 선택지, 획일적으로 반복되는 질문, 주관식 답변 요구 등이 응답자의 판단과 작성 부담을 증가시킴. (로그 7, 10)
2. **제작자 페인**
    1. **반복적인 문항 제작 부담** [문제] — 질문 수가 많아질수록 문항을 하나씩 따로 제작해야 하고, 반복되는 기본 문항도 매번 다시 만들어야 해 제작 공수가 증가함. (로그 1, 3)
    2. **데이터 분석 및 외부 연동 부담** [문제, 우회로] — 자체 분석 기능이 부족하고 결과 데이터를 엑셀 등 외부 도구와 연동해 사용해야 하며, 중복 응답을 처리하는 과정에서도 착오가 발생함. (로그 1, 2)
    3. **시각적 표현 및 브랜딩의 한계** [제약] — 폼을 그림, 영상 등으로 보다 직관적으로 전달하고 싶어도 기존 폼은 표현 방식에 제약이 있고 이에 서비스나 브랜드에 맞게 폼을 꾸미기 어려움. (로그 6, 8)
    4. **입력 양식 및 응답 형식의 비일관성** [문제] — 전화번호 등 입력 필드의 포맷이 통일되지 않거나 응답 형식이 서로 다르게 수집되어 이후 데이터 정리와 가공에 추가 공수가 발생함. (로그 6, 8)

### D.핵심 Job Story

**핵심 Job Story 1 — 제작자**

> 폼을 제작하고 수집된 응답을 실제 운영에 활용해야 할 때, 나는 반복되는 문항을 빠르게 구성하고 흩어진 응답을 쉽게 확인·정리하고 싶다. 그래서 여러 도구를 오가는 제작·분석 수고를 줄이면서 필요한 응답을 놓치지 않고 후속 업무까지 효율적으로 처리할 수 있도록. (로그 1, 2, 3, 6, 8, 관찰 1)
>

| 요소 | 내용 | 근거 |
| --- | --- | --- |
| 상황(트리거) | 반복적으로 폼을 제작하고 다수의 응답을 수집한 뒤, 실제 선발·관리·정산 등의 후속 업무에 활용해야 하는 상황. 문항 수가 많거나 응답 형식이 다양하고 데이터 확인 과정이 복잡할수록 문제가 크게 나타남 | 로그 1, 2, 3, 6, 8, 관찰 1 |
| 기능적 Job | 반복되고 자주 사용하는 질문을 빠르게 구성하고, 수집된 응답을 기준에 따라 빠르게 검색·정리하여 별도의 복잡한 데이터 처리 과정 없이 필요한 정보를 파악하고 싶음 | 로그 1, 2, 3, 6, 8, 관찰 1 |
| 감정적 Job | 문항·설정 누락, 중복 응답 처리 오류, 결제 상태와 응답 데이터 불일치로 인한 재확인 작업을 줄이고 싶음. 응답자의 중도이탈에 대한 우려를 완화하고자 함 | 로그 1, 3, 6 |
| 사회적 Job | 여러 운영진이 동일한 응답 데이터를 기반으로 별도의 파일 정리나 반복적인 설명 없이 효율적으로 의견을 공유하고 협업하고자 함. | 로그3, 10 관찰 1 |
| 현재 고용된 대안 | 폼 제작 시 기존 설문을 별도 창에서 참고하며, 응답 확인 시 Google Forms와 연동된 Sheets를 번갈아 확인함. 면접 평가 및 추가 질문은 별도로 기록하고, 대규모 응답은 파일을 분할하여 Google Drive로 공유하며, 계좌정보는 은행 앱에서 별도로 확인함. | 관찰 1 |

**전환의 네 힘**

| 힘 | 내용 | 근거 |
| --- | --- | --- |
| Push | 문항이 많아질수록 질문을 하나씩 만드는 시간이 늘고, 기존 문항을 사용하기 위해 이전 폼을 반복해서 참고해야 함. 응답을 확인할 때에도 Forms와 Sheets를 여러 차례 오가며, 분석 기능 부족·응답 형식 불일치·중복 응답 처리 등으로 추가적인 정리 작업이 발생함 | 로그 1, 2, 3, 6, 8, 관찰 1 |
| Pull | 자주 사용하는 문항을 빠르게 구성하고, 수집된 응답을 자동으로 분류·정리한다. Sheets의 복잡한 기능을 몰라도 필요한 응답을 찾거나 결과에 대해 질문하고 바로 확인할 수 있는 환경 — **아직 가설**, 인터뷰로 검증되지 않음 | (가설) |
| Anxiety | 기존의 직접 확인 방식이 아닌 자동으로 분류·정리된 결과를 제작자가 어느 정도 신뢰해야 하는지에 대해서는 현재 로그에서 직접 확인되지 않음. 후속 검증 필요 | 추가 검증 필요 |
| Habit | 이전에 제작한 폼을 복사하거나 참고하고, Google Forms와 Sheets를 연동한 뒤 필요한 경우 은행 앱·Google Drive까지 함께 사용하는 현재 작업 방식에 익숙해져 있음 | 관찰 1 |
- 온톨로지로 되쓰기: `User → Form → Result`

**핵심 Job Story 2 — 응답자**

> 폼에 응답해야 할 때, 나는 이미 입력한 정보를 반복해서 작성하거나 여러 외부 도구를 오가지 않고 필요한 답변을 부담 적게 완성하고 싶다. 그래서 마감이나 작성 내용을 놓치지 않고, 내가 무엇을 작성하고 제출했는지 확인하면서 안심하고 응답을 끝낼 수 있도록. (로그 2, 3, 4, 6, 7, 9, 10, 관찰 2)
>

| 요소 | 내용 | 근거 |
| --- | --- | --- |
| 상황(트리거) | 개인정보, 긴 주관식 답변, 파일 제출이나 계좌이체 등이 포함된 폼에 응답해야 하는 상황. 분량이 길거나 별도의 정보 확인·작성 도구가 필요할수록 응답 부담이 커짐 | 로그 2, 3, 4, 7, 9, 10, 관찰 2 |
| 기능적 Job | 이름·연락처 등 이전에 작성한 정보를 반복해서 입력하는 일을 줄이고, 현재 글 분량과 진행 상태를 확인하면서 긴 주관식 답변을 효율적으로 정리하여 마감 전 제출을 완료하고자 함. | 로그 2, 3, 7, 9, 10, 관찰 2 |
| 감정적 Job | 개인정보를 제출할 때의 불안, 설문이 얼마나 남았는지 모르는 답답함, 제출 후 “제대로 작성했나”라는 걱정을 줄이고 안심한 상태로 제출하고 싶음 | 로그 3, 4, 6, 9 |
| 사회적 Job | 주관식 답변을 지나치게 짧거나 어설프게 작성해 성의 없고 가볍게 보이고 싶지는 않지만, 긴 답변을 완성도 높게 작성하는 데 많은 시간을 쓰고 싶지도 않음. 맞춤법이나 어색한 표현 때문에 자신의 답변이 좋지 않은 인상을 주는 것도 피하고 싶음 | 관찰 2 |
| 현재 고용된 대안 | 긴 주관식 답변을 직접 작성한 뒤 외부 글자수 세기 서비스를 이용해 분량을 확인하고, 외부 AI에서 글을 다듬은 후 결과를 다시 폼으로 복사함. 계좌이체가 필요하면 모바일 은행 앱으로 이동함 | 관찰 2 |

**전환의 네 힘**

| 힘 | 내용 | 근거 |
| --- | --- | --- |
| Push | 기본정보를 반복 입력해야 하고 긴 주관식 문항 작성에 시간이 오래 걸리며, 설문의 남은 분량이나 제출한 내용을 다시 확인하기 어려움. 실제 관찰에서는 글자수를 확인하고 문장을 다듬기 위해 외부 화면으로 6회 이동했으며, 마감기한을 놓쳐 제출하지 못한 경험도 있음 | 로그 2, 3, 4, 6, 7, 9, 10, 관찰 2 |
| Pull | 한 계정에서 반복되는 기본정보를 자동 입력하고, 작성 중인 폼과 마감 일정을 이어서 관리하며, 주관식 작성 과정에서 현재 글자수를 바로 확인하고 필요할 때 짧은 초안을 자연스러운 문장으로 정돈할 수 있는 응답 환경 — **아직 가설**, 인터뷰로 검증되지 않음 | (가설) |
