`./gradlew test --tests '*GoldenTest'`를 실행하고, 결과를 `tests/harness/golden_cases.yaml` 및 구현과 대조해 보고한다.

## 규칙

- 소스, 테스트, 케이스, 설정, `data/seed` 어떤 파일도 수정하지 않는다.
- 실행하지 못하면(예: `gradlew` 없음, 골든 테스트 없음, 케이스 파일이 비어 있음) 이유를 그대로 보고한다. 통과로 추정하지 않는다.
- 실행되지 않았거나 skip된 케이스를 통과로 세지 않는다.
- 실패가 있으면 수정 위치와 이유만 제안한다. 실제 수정은 별도 위임으로 한다.

## 절차

1. 위 명령을 그대로 실행하고 종료 상태를 기록한다.
2. 결과는 `build/test-results/**/*.xml`에서 읽는다. `test` 태스크가 `UP-TO-DATE`이거나 `FROM-CACHE`였다면 이번 실행에서 다시 돌리지 않았다고 밝힌다.
3. `tests/harness/golden_cases.yaml`의 케이스 id와 실행 결과를 대조한다.
   - YAML에 있는데 실행되지 않은 케이스는 "미실행"이다.
   - 실행됐는데 YAML에 없는 테스트는 따로 표시한다.
4. 통과한 케이스도 구현의 어느 코드 때문에 통과하는지 읽고 한 줄로 설명한다(`AGENTS.md` 4절 3항).
5. `git status --short`로 추적 파일이 바뀌었는지 확인한다.

## 보고 형식

- 명령과 종료 상태
- 합계: 전체 케이스 수, 통과, 실패, skip, 미실행
- 케이스 표:

| 케이스 id | 결과(통과/실패/skip/미실행) | 판정 근거(코드 위치와 한 줄 설명) | skip 사유 |
|---|---|---|---|

- 실패 케이스별 수정 제안: 수정 위치와 이유
- YAML에 없는 테스트 목록
