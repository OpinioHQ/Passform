`./gradlew build`를 실행하고 결과를 보고한다.

## 규칙

- 어떤 파일도 수정하지 않는다. Gradle이 만드는 `build/` 산출물 외의 변경이 생기면 보고한다.
- 명령을 실행하지 못하면(예: `gradlew` 없음) 이유를 그대로 보고한다. 통과로 추정하지 않는다.
- `@Disabled`나 skip된 필수 케이스를 완료로 처리하지 않는다.
- 실패하면 원인과 수정 제안만 적는다. 수정은 하지 않는다.
- 최종 수용 여부는 사람이 정한다. 결론을 "수용 가능"으로 내리지 않는다.

## 절차

1. `./gradlew build`를 실행하고 종료 상태를 기록한다.
2. 테스트 결과는 콘솔 출력만 믿지 않고 `build/test-results/**/*.xml`에서 집계한다. 결과 파일이 없으면 "결과 없음"으로 보고한다.
3. 클래스 이름이 `GoldenTest`로 끝나는 테스트를 골든 테스트로, 나머지를 그 밖의 테스트로 나눈다.
4. `test` 태스크가 `UP-TO-DATE`이거나 `FROM-CACHE`였다면 이번 실행에서 테스트를 다시 돌리지 않았다고 밝힌다.
5. `git status --short`로 추적 파일이 바뀌었는지 확인한다.

## 보고 형식

- 명령과 종료 상태
- 집계 표:

| 구분 | passed | failed | skipped |
|---|---|---|---|
| 골든 테스트 (`*GoldenTest`) | | | |
| 그 밖의 테스트 | | | |

- skipped 목록: 테스트 이름과 사유. 사유가 없으면 "사유 없음"으로 적는다.
- failed 목록: 테스트 이름, 원인, 수정 제안
- 골든 테스트가 0건이면 통과가 아니라 "골든 테스트 없음"으로 적는다.
- 빌드 성공이 곧 완료를 뜻하지 않는다. `AGENTS.md` 6절의 나머지 항목(프런트엔드 검사, GitHub Actions)은 이 명령으로 확인하지 않았다고 밝힌다.
