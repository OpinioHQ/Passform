# 화면 디자인 체계 적용 위임 기록 (#106)

기록 대상: 프론트 전체 화면 디자인 체계 적용. 실행일 2026-11-10. 프롬프트는 프롬프트 세션에서 쓴 초안을 사람이 검토해 발행했고 §1에 요지를 둔다.

## §1 프롬프트 요지

- 목표: 외부 SaaS 디자인 분석 문서(`DESIGN-cal.md`, 저장소 밖)를 기준으로 앱 전체에 한 벌의 디자인 체계를 입혀 11/11 시연에서 깔끔하고 믿음직하게 보이게 한다.
- 절대 규칙: 화면 글자, class 이름, DOM 구조, aria 속성, 테스트 id, 동작(라우팅·저장·검증·자동 저장·경고)을 바꾸지 않는다. 기존 시험·판정 기준 파일·백엔드·API 타입을 고치지 않는다. 홈의 개인정보처리방침 링크(`/privacy.html`)를 남긴다. 360px에서 응답 화면이 가로로 넘치지 않는다.
- 새 의존성은 `pretendard` 하나(사람 승인, 자체 호스팅, 외부 CDN 금지).
- 비용 규칙: 서브에이전트 없음, SPEC 읽지 않음, `styles.css`는 검색해 필요한 곳만 고침, 단계마다 로컬 커밋과 짧은 보고.
- 순서: 1단계 토큰·공통 요소 → 2단계 시연 경로(홈 → 응답 → 내 폼함·제출 내역 → 내가 만든 폼 → 빌더 → 결과 → 탐색) → 3단계 남은 화면과 안 쓰는 CSS 정리.
- 중단 조건: 시험을 고쳐야만 통과할 때, 구조나 글자를 바꿔야 할 때, 백엔드·API 타입을 건드려야 할 때, 같은 실패로 3회차를 넘길 때 객관식으로 묻는다.

## §2 기준 문서 요약 (DESIGN-cal.md를 이렇게 적용했다)

| 항목 | 적용 |
| --- | --- |
| 색 | 문서 colors를 `:root` CSS 변수로 그대로 옮김. 흰 캔버스, 검정 주 버튼(#111111, 눌림 #242424), 본문 #374151, 보조 #6b7280, 경계선 #e5e7eb, 연회색 카드 #f5f5f5. 파란 강조는 링크·파란 배지·홈 pill 한 곳만 |
| 글꼴 | Cal Sans·Inter 대신 Pretendard 하나. 제목 600·음수 자간(-0.5px 안팎), 본문 400, 버튼 14px 600 |
| 간격·모서리 | 4px 단위. 버튼·입력 8px, 카드 12px, 큰 영역 16px, 배지 pill. 96px 띠 간격은 홈에만 |

| 화면 성격 | 앱 화면은 흰 바탕+카드+표로 조용하게, 홈만 hero·기능 카드·어두운 하단 |
| 쓰지 않은 것 | Cal.com 이름·로고·문구·그림 |

## §3 사람 결정

1. 이슈는 새로 만든다(#106). 커밋·PR 태그는 README 표에 있는 `style`.
2. 오류 글자색은 대비 때문에 #b91c1c를 쓴다(바탕·테두리는 옅은 빨강).
3. 제작자 화면은 로컬 실제 API(5175 + 백엔드 8080)로 사람이 로그인해 본다.
4. 홈 포인트 색은 brand-accent를 hero pill 한 곳에만 쓴다. hero를 연회색 면으로 감싼 안은 사람이 보고 되돌렸다(이전 모양 유지).
5. 내가 만든 폼(실제 API)에 가상 데이터 화면과 같은 "새로운 폼을 만들어보세요" 상자를 둔다(`demo/DemoCreatedPage.tsx:52-61`에서 가져옴).
6. 비로그인 안내는 상자와 검정 버튼 모양만 통일한다(버튼 글자와 이동은 화면마다 그대로). 내가 만든 폼은 로그인 화면으로 보내지 않고 화면 틀 안에 안내를 보인다.
7. 사람이 승인한 글자 변경 3개
   - 홈 03 카드 "답변 도우미" → "탐색 도우미"(`LandingPage.tsx`)
   - 제출 내역 화면 제목 "제출한 답변" → "제출 내역"(`HistoryPage.tsx`)
   - 응답 화면 버튼 "작성한 답 지우기" → "응답 전체 지우기"(`ResponsePage.tsx`)
   - 홈 01 카드 설명도 사람이 지정한 문구로 바꿨다("받은 폼을 내 폼함에 저장하세요. 중단한 폼은 이어 쓰고, 제출한 답을 다시 확인하세요.").
8. 사람이 승인한 시험 변경 위치(단언과 기대 의미는 그대로, 문구만)
   - `frontend/src/App.routes.test.tsx:43-44` 기대 제목 "제출 내역"
   - `frontend/src/response/DraftGate.test.tsx:450, 461` 시험 제목과 버튼 이름
   - `frontend/src/response/DraftGate.review.test.tsx:5, 172` 설명 주석과 버튼 이름
9. 로컬 `npm test`는 이 PC의 시간 초과 문제로 보고 CI로 판단한다.

## §5 확인 방법과 남은 것

- 화면 확인은 로컬 Chrome 스크린샷으로 1280px·360px을 보고, 360px 가로 넘침(`scrollWidth`)을 쟀다. 제작자 화면은 API 응답을 가짜로 채운 브라우저로 먼저 보고 사람이 실제 로그인으로 확인했다.
- 화살표 아이콘(`arrow-right.svg`)은 선이 흰색이라 흰 버튼 위에서는 CSS로 검게 바꾼다. 아이콘 파일은 그대로다.
- `creatorRoutes.tsx:323` 주석과 `docs/prompts/delegation_response_draft.md`에는 옛 용어가 남아 있다(기록이라 그대로 둠).
